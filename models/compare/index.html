Compare JevStyle 0.8B v3 and 2B v4

Choose a local decision model by the inputs and hardware you have, then validate its decisions on your own task.

Compare modelsEvaluate your data

Source review: 29 October 2026 · Open weights · Apache-2.0

Which JevStyle model should I start with?

Start with 0.8B v3 for a smaller text-only baseline. Choose 2B v4 with PyTorch when the input includes images, or evaluate it as a larger text model. Both score predefined options rather than generate free-form text. Neither choice guarantees accuracy on a new task.

For ticket labels, workflow routes, yes/no checks, and ordered scores, first define the decisions you need. Then measure both releases on the same held-out requests. A larger model's published score alone does not determine its quality, memory use, or speed in your application.

Sizes are published weight-file totals in decimal GB, not peak RAM/VRAM, default downloads, or storage for every backend. Runtime state, inputs, framework overhead, and image processing need additional memory. The project recommends Q8_0 or F16 for long 2B text inputs; a smaller quantized file is not automatically equivalent in quality.

Run a local baseline

Use Python 3.10 or newer in a virtual environment. For Apple silicon text input:

bash
python -m pip install "jev-style[mlx]"
jev-style serve --release 0.8b

For the 2B v4 PyTorch build, including image input:

bash
python -m pip install "jev-style[torch]"
jev-style serve --release 2b --backend torch

The first run downloads the model. Once the server is ready, open the local Playground. To compare releases, keep your input set and decision definitions fixed, use separate ports, and follow the evaluation guide.

The hosted API is a separate service with its own available model, input cap, and service status. Do not apply these local limits to it; consult API documentation.

Model selection questions

Can I use JevStyle offline?

Local inference can run without sending decision inputs to a hosted model after the required package, weights, and runtime files have been downloaded. The browser demo and hosted API are separate online services.

Is a 0.53 GB file the total memory requirement?

No. It is the 0.8B Q4_K_M GGUF weight file. Runtime memory is larger and depends on the backend and input. The default package setup does not necessarily choose that file.

Can the MLX or GGUF version of 2B v4 read images?

No. Those distributions contain the language model only. Choose the 2B v4 PyTorch distribution and matching runtime for image input.

Should I always choose the larger model?

No. Compare task accuracy, calibration, warm latency, memory, and review coverage on your own examples. Keep a person or existing LLM available for ambiguous cases and runtime failures.
