Use cases / Local routing

Give routine decisions a local route.

Route requests to a tool, team, or workflow with JevStyle. Read a probability for every option and send uncertain cases to a person or your existing LLM.

Try the HF demo ↗Run locally ↓View on GitHub ↗

Open weights · Apache-2.0 · Examples for jev-style 0.6.0

One request, a defined set of choices

If your application asks an LLM to return a label such as billing or shipping, that step can be evaluated separately from the rest of the conversation. JevStyle scores the choices you define in one forward pass.

Incoming request→Local model scores your routes→Selected workflow or review

This example proposes a destination. It does not invoke a tool or perform a customer action. Keep authorization and execution checks in your application.

Start a local decision server

Use Python 3.10 or newer in a virtual environment. Install the backend for your machine, then keep the server running in this terminal.

bash
# Apple silicon
python -m pip install "jev-style[mlx]"

# Linux, Windows, or an Intel Mac: use this instead
# python -m pip install "jev-style[torch]"

jev-style serve --release 0.8b

The first run downloads the model. Once it is ready, open the local Playground. Run the Python examples in a second terminal with the same environment.

Score a request and keep a fallback

Save this as route.py and run python route.py. The route descriptions are part of the model input: keep them specific and mutually understandable.

python
import json
from jev_style import JevStyle, choice

# Illustrative threshold: select yours on held-out labelled examples.
threshold = 0.90

with JevStyle(base_url="http://127.0.0.1:8765") as model:
    result = model.decide(
        "I need to change the delivery address for order 4411.",
        {"route": choice("Which workflow should handle this request?", {
            "billing": "Charges, payments, invoices, and refunds",
            "shipping": "Delivery status and delivery address changes",
            "account": "Login, password, and profile settings",
            "other": "Requests outside the workflows above",
        })},
    )

answer = result["answers"]["route"]
label = answer["choice"]
top_probability = max(answer["probabilities"].values())
needs_review = label == "other" or top_probability < threshold
print(json.dumps({
    "proposed_route": label,
    "top_probability": top_probability,
    "next_step": "human_or_llm_review" if needs_review else label,
}, indent=2))

Choose the threshold on your data. The 0.90 value demonstrates the control flow; it is not a recommended production setting. Use the maximum option probability here. The API’s confidence field is a separate normalized quantity.

Move one decision before moving a workflow

  1. Collect representative requests and label the correct route, including ambiguous and out-of-scope cases.
  2. Run the local model alongside the existing process. Record route agreement, mistakes, latency, and the share of cases sent for review.
  3. Use a held-out set to check a fixed threshold before letting local decisions affect routing.
  4. Keep the existing LLM or human queue available for uncertain answers and runtime failures.

npx skills add lawrence3699/jev-style --skill jev-style-adopt

Use your existing Semantic Router workflow

Semantic Router 1.1.1 includes SystemOneDecisionModel, which can call JevStyle’s local endpoint without an external API key. Its DecisionRouter uses route descriptions as choice options.

With your JevStyle server running, install the integration dependency and run the complete example from a clone of this repository:

bash
python -m pip install "semantic-router==1.1.1"
python examples/semantic_router_local.py "Where is my parcel?" --threshold 0.90

The complete example discovers the server’s model ID, returns a review step when no route clears the threshold, and reports connection failures without choosing a business action. Its 0.90 threshold is illustrative. It requires Python 3.10–3.13.

The request/response path and fallback behavior were checked with the published Semantic Router 1.1.1 client against a local JevStyle HTTP server using the fake engine. That verifies the integration contract; evaluate the real model separately before using its decisions.

Where this approach fits

Use it for defined choices, yes/no checks, and ordered scores. Keep open-ended writing, conversation, and complex reasoning in the system best suited to those jobs. Adding other is useful, but it does not guarantee that every unfamiliar request will be rejected.

Local execution avoids sending decision inputs to a hosted model after the weights have downloaded. The Hugging Face demo is hosted separately. Actual latency depends on your hardware, input length, backend, and model; measure end-to-end time including fallback calls.
