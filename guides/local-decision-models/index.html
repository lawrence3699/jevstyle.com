Guides / Local decisions

Choose a local decision model for classification and routing

Start with the output you need: a label, a similarity score, probabilities over fixed options, or generated text. That choice matters more than the model's parameter count.

Compare approachesRun on your machine

Source review: 29 October 2026 · Commands follow jev-style 0.6.2 · No cross-tool speed ranking is claimed

When to use this local approach

JevStyle is a local option for scoring predefined choices on Apple silicon with MLX, or on CPU/CUDA with PyTorch. Choose it when you need typed option probabilities; keep a generative model when you also need a written reply. See the named-tool comparison and Semantic Router integration.

Match the method to the decision

If you have representative labeled text and stable categories, build a supervised classifier as a baseline. If routes are described by example utterances, evaluate an embedding router. If the decision depends on instructions and a fixed set of options, evaluate a typed decision model such as JevStyle. If you also need a written answer or flexible extraction, keep a local generative model in the comparison.

These are alternatives to test, not a universal ordering. A model that succeeds on a public benchmark can still fail on your languages, labels, documents, or unusual inputs. Keep the input set fixed when comparing methods.

The scikit-learn text feature guide describes bag-of-words and TF–IDF representations. Semantic Router's local quickstart demonstrates routes built from utterances and a local embedding model. These offer useful baselines alongside instruction-driven decision models.

For generated output, llama.cpp's grammar documentation explains output constraints. A valid JSON object still needs application-level checks: a syntactically valid {"team":"billing"} can select the wrong team.

When fixed-option scoring is a useful fit

Consider a service request: “I was charged twice.” A classifier might assign billing; an embedding router might match a billing example; a typed decision model can score your defined destinations and a separate refund question. A generative model can also propose a label, but generating a paragraph is unnecessary if the next component only accepts a route.

JevStyle is one open-source implementation of the typed-decision approach. Its local API returns probabilities over supplied options; your application decides whether to accept the result or send it for review. It does not execute a selected action. Multiple questions may share one input state, for example team, refund intent, and urgency.

Use the local text classification tutorial for a Python implementation, the routing guide for a fallback workflow, or the Claude Code guard guide for an additional tool-call review signal. A probabilistic guard is not a sandbox or authorization system.

Running local decisions on Apple silicon

A runtime and a model are different choices. MLX LM provides local language-model generation and fine-tuning on Apple silicon. llama.cpp supports local inference across hardware, including Apple silicon. JevStyle supplies matching decision runtimes for its own models; its probability outputs do not come from a generic text-generation command.

Start a local server and score a choice

Use Python 3.10 or newer in a virtual environment. Choose one setup below for the same local API. The first start downloads model files; later requests can use the downloaded assets without the hosted JevStyle service.

Apple silicon · text
python -m pip install "jev-style[mlx]"
jev-style serve --release 0.8b --backend mlx
PyTorch · 2B v4 text and images
python -m pip install "jev-style[torch]"
jev-style serve --release 2b --backend torch
CPU-only · text baseline
python -m pip install "jev-style[torch]"
jev-style serve --release 0.8b --backend torch --device cpu

Leave the server running. In a second terminal with the same environment:

One decision through the local endpoint
jev-style decide "I was charged twice" \
  --url http://127.0.0.1:8765 \
  --choice "Which team should handle this request?::billing,shipping,account"

The command prints the actual model result; this page does not promise a particular prediction. Open the local Playground to inspect options and scores. For GGUF, use the package's matching scorer instructions instead of substituting a generic chat runner.

Make the comparison on your workload

  1. Define the correct decision and collect representative examples, including ambiguous, rare, and out-of-scope inputs.
  2. Fix a final test set before tuning prompts, route descriptions, or thresholds. Record model revision, backend, precision, and hardware.
  3. Compare errors per class, calibration, accepted-request coverage, and end-to-end latency. Include serialization, queueing, and fallback requests if they are part of production.
  4. Send low-confidence outputs and runtime failures to a person or existing LLM. Test how that fallback behaves before automating downstream actions.

A threshold such as 0.90 is not a general safety rule. An embedding similarity, a model's option probability, and a transformed confidence field are different quantities. Choose the threshold using the actual score exposed by the method you deploy.

Follow the evaluation and threshold guide. The published JevStyle benchmark page records existing self-runs and their limitations; it is not a head-to-head test of the four approaches on this page.

Common selection questions

Do I need a generative LLM to return a label?

No. A supervised classifier, embedding router, or typed decision model may fit that step. A generative model remains useful when the task also needs an explanation, extraction, or open-ended response. Compare against a simple baseline before replacing an existing system.

Can I score options locally without sending private inputs to a hosted API?

Yes, if the model, encoder, and inference path run locally. Download the required dependencies and model assets first, and check the configuration of every component in the workflow. JevStyle's hosted API and Hugging Face demos are separate remote services.

Are embedding scores and decision-model probabilities interchangeable?

No. Similarity measures match in an embedding space; option probabilities belong to a particular model, input, and choice set. Neither guarantees correctness on a new domain. Calibrate and validate the acceptance rule for the score you actually use.

Can stock Ollama or MLX generation commands return JevStyle decision scores?

Use those tools for compatible generative models. JevStyle's current decision releases require their matching decision runtime to expose option probabilities. Use the package's MLX, PyTorch, or GGUF setup rather than treating decision weights as an ordinary chat model.

Is the largest model always the right choice?

No. Accuracy, memory, warm and cold latency, and fallback frequency depend on the workload and backend. Compare them on the same held-out inputs. A model's download size or public benchmark result alone does not settle that choice.
