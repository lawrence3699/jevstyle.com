Measured local support routing comparison

Our reproducible six-intent BANKING77 experiment compares JevStyle 0.8B v3 (MLX 8-bit, no task fine-tuning) with a TF-IDF classifier trained on 738 labeled examples. On 240 held-out requests, the classifier scored 229/240 and JevStyle 224/240; the classifier was also faster. The page includes all predictions, source IDs, package versions and a development threshold that missed its held-out error target. It is a project self-run with different supervision, not a general ranking or production threshold recommendation.

Published results, with their limits

JevStyle publishes decision-model results on JevBench and the Decision Index. The values below are project self-runs, not independent certifications or official leaderboard ranks. They describe particular model revisions, datasets, and runtimes.

The latest 2B v4 reports 74.9% accuracy on 231 public JevBench v1.4.1 items, a 44.37 Decision Index 0.3 public score, and a 57.55 public Vision score. These are different metrics: only the first is a percentage accuracy. Sources: 2B v4 model card, pinned revision and 0.8B v3 model card, pinned revision.

Model repository creation dates are 27 October 2026 for 2B v4 and 24 September 2026 for 0.8B v3. They are release metadata, not benchmark run timestamps. This page consolidates existing reports; it does not claim that a new evaluation was performed on the source-review date.

These are in-process request wall times. Model loading and CUDA graph recording are excluded. They do not measure HTTP transport, client-side work, queueing, or fallback to another model, and are not an estimate for your CPU, Mac, or hosted endpoint. See the pinned speed protocol.

For deployment decisions, time cold start, warm p50/p95, concurrent load, and the complete route including fallbacks on your own hardware. Compare quality and latency on the same input distribution.

Sources and reproduction

  • 2B v4 protocol and training provenance: pinned source for all 2B rows above.
  • 2B v4 published Decision Index evaluation adapter: use with the kit version stated in the model card.
  • JevBench v1.4.1 harness: retain the public-item split and request format when comparing a new run.
  • 0.8B v3 JevBench chart data and full source card: published counts, uncertainty, and provenance.
  • Evaluate your own labeled requests: save the data version, model revision, backend, precision, hardware, and error/coverage counts with the report.

For a new run, pin both the model revision and the evaluation tool revision. Do not reuse the headline numbers for quantized weights, another backend, altered prompts, or a different dataset without checking them again. A model's published global calibration is not evidence that its probabilities remain calibrated in every domain.

Benchmark questions

Is 44.37 an accuracy percentage?

No. It is the Decision Index 0.3 composite public score. Use the per-benchmark metric and protocol when interpreting an individual task.

Do these numbers prove 2B v4 will work better on my tickets?

No. Evaluate the language, labels, ambiguous cases, and class mix you expect to see. Measure the error rate and the share of requests sent for review under a fixed threshold.

Was every task evaluated zero-shot?

No. The source card marks training overlap and distinguishes held-out evaluation rows from whether a benchmark's training split was used. Consult each dataset's protocol before claiming zero-shot performance.

Where is the hosted API's response-time guarantee?

These local model experiments provide no hosted API latency guarantee. Check current service information separately.
